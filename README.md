# 音高球 PitchBall

实时人声音高测量工具(Windows,WPF / .NET 8,单文件便携版)。

- 🎯 **实时音高检测**:悬浮小球实时显示音名、频率、音分(麦克风 / 系统声音 / 正在播放的应用三种音源);
- 🎤 **声区识别**:自动区分并标注 真声 / 混声 / 假声,假声高音不丢失、不跳八度;
- 📊 **离线分析**:拖入音频文件即得整曲音高曲线(波形图悬停查看任意时刻音高,滚轮缩放、拖动平移);
- 🧠 **RMVPE 神经人声模型(可选算法)**:在密集混音/现场演唱会里,伴奏或和声比人声更强时,
  pYIN 会被抢线,YIN 系算法同理;RMVPE 的判据是从大量人声数据学到的音色特征,仍能锁住人声
  (实测漏音事件少 2~3 倍、中断总时长少 60~70%);
- 🎛 **人声场景三档**:通用 / 纯净CD版 / 演唱会版——按素材选择低音抑制策略;
- 🧭 **和声/多声部鲁棒**:观测概率时间平滑 + 锚点式防跳变,和声丰富的段落也能锁定主旋律;
- 🎨 **个性外观**:背景图(带虚化)、强调色(可跟随背景自动取色)、小球配色(按音级 / 按声区 / 按声部·男/女低中高);
- 🎬 **新手引导**:首次启动自动演示核心界面,设置里可随时重新查看;
- ⚙️ **分析选项**:拖入文件时可选择检测算法与人声场景(可记住选择)。

## 更新日志

**v1.2.1**

- **修复:实时模式下 RMVPE 会让界面卡死。** 实时封装原先用 NAudio 的
  `BufferedWaveProvider`+`WdlResamplingSampleProvider` 做 push 语义的重采样,其中
  `ReadFully=true` 使排空循环永远读不到 0(死循环卡住采集回调),且输出的音频实际无法被
  模型识别(窗内置信度只有 0.002)。现改为自写、可验证的 Hann 窗 sinc 分数重采样
  (`SincResampler`,截止取输出奈奎斯特自带抗混叠)。实测同一段素材实时与离线输出一致
  (520.6Hz vs 520.8Hz),窗内置信度 0.002 → 0.966。
- **修复:关于面板里版本号一直显示 v1.0.0。** 该文本原先在 `MainWindow.xaml` 里写死,升级后不会变;
  现改为运行时从程序集版本生成(以后升级自动同步)。

**v1.2.0**

- **新增 RMVPE 神经人声模型(第三种检测算法)。** 这一版解决的是此前记录在"已知边界"里的问题:
  密集混音(典型是现场演唱会)中伴奏/和声与人声同频段且更强时,基于周期性的 pYIN 与手写 YIN
  都会锁到伴奏。RMVPE 用音色特征判据,实测:
  - 5 个真实素材对照 pYIN:漏音事件少 **2~3 倍**、中断总时长少 **60~70%**、有声率 **90~96%**(pYIN 69~88%);
  - 13 首录音室/现场 R&B 素材对照:pYIN 普遍偏低 0.5~1.5 个八度(把伴奏/和声当成了基频),
    RMVPE 报在旋律所在的八度;反向(RMVPE 偏低)的情形明显更少;
  - 纯 CPU:每秒音频约 8~13ms(比 pYIN 更省),**不需要 GPU**;
  - 体积:模型 INT8 量化 94MB(原 fp32 345MB),单文件 exe 由 140MB 增至约 **250MB**。
  - 已知代价:实时模式下 RMVPE 以约 0.25s 间隔后台推理(音高更新比 pYIN 慢);声区标注暂沿用真声。
- 检测算法选择器新增 RMVPE 项(设置面板与拖入文件时的分析选项)。

**v1.1.2**

- **修复:高音被报成低 2~4 个八度。** 周期信号在 T、2T、3T… 处的 CMNDF 谷几乎等深,而 HMM 的转移窗口只有 ±1 半音、跨八度需要十几个中间状态(那些状态没有候选、观测为 0),因此一旦在音头处锁到次谐波,整段高音都会显示成低八度——即使候选概率完全支持真基频(实测 645Hz 候选概率 0.850、162Hz 幻音 0.005,输出仍是 162Hz)。现按「上报音高在频谱上几乎不存在(自身基波与低阶谐波皆无)、而另有候选支撑充分」判定并改写。假声/头声这类"基波弱但确实存在"的帧不受影响:其 2 次谐波就是那个强谱峰。实测(142 分钟现场录音):整段被报成低八度的高音得到修正,而基波较弱的假声/头声帧保持不变;4 首流行歌的有声率与音高分布无变化。
- **修复:实时管线 `yinTrust` 0.5 → 0.7,与离线管线对齐。** 离线端此前已针对"弱高音在边际上抖动而丢失"改用 0.7,实时端没有同步,同一素材在实时模式下漏音更多。实测 4 个文件漏音帧减少 0~26%,代价是弱帧虚警提高 0.4~2.4 个百分点。
- **已知边界(非本版引入):** 在密集混音中(典型是现场演唱会),若伴奏或和声占据了与人声相同的频段,基于周期性的基频检测器只能锁住"最强的周期源"——当人声不是最强时会被伴奏抢线。这与 Melodyne 等商业工具的行为一致(其官方建议先做分轨)。此类素材可对比「检测算法 / 人声场景」档位,或改用麦克风音源。

## 常见问题

**双击没反应 / 打不开?**

1. **杀毒软件拦截**:PitchBall 是未签名的开源软件,360、腾讯电脑管家、火绒、Defender 等可能静默拦截。请到杀毒软件"隔离区/恢复区"找回 `PitchBall.exe` 并**添加信任**;Windows Defender 在"安全中心 → 保护历史记录"里允许即可。源码全部公开,可放心信任。
2. **SmartScreen 提示**:浏览器下载的文件会被 Windows 标记。若弹出"Windows 已保护你的电脑",点"**更多信息 → 仍要运行**";或右键文件 → 属性 → 勾选"**解除锁定**" → 应用。
3. **下载不完整**:v1.2.1 完整大小为 **263,282,334 字节**(约 251.1 MB),SHA256 校验值:
   ```
   00736661787818A5D659B78DA13AAF1B824FDDD2C1B0A1B81C91BD66DC7E9D55
   ```
   对不上就重新下载。校验方法:`certutil -hashfile PitchBall.exe SHA256`。
4. **第一次启动较慢**:单文件自包含版首次运行要把运行时解压到临时目录,机械硬盘上可能需要 10~30 秒才出现窗口,请耐心等待,可在任务管理器里确认 `PitchBall.exe` 进程已存在。
5. **系统要求**:Windows 10 1607 及以上(64 位),Windows 7/8 无法运行。

**闪退 / 报错怎么办?**

程序会把崩溃详情自动记录到 `%APPDATA%\PitchBall\crash.log`(在资源管理器地址栏粘贴该路径回车即可打开)。把该文件发给开发者或提交到 GitHub Issues,即可快速定位问题。

**某段高音检测不到 / 显示的比实际低一个八度?**

先试这三步,基本能定位:

1. **把「检测算法」切成 RMVPE**(v1.2.0 新增)。密集混音里伴奏/和声与人声同频段且更强时,pYIN 与手写 YIN
   都会锁到伴奏(这是"找最强周期源"的固有边界,商业工具如 Melodyne 同样是这个行为);RMVPE 用音色特征判据,
   实测能锁住人声。代价是单文件体积变大(约 250MB)与实时更新稍慢。
2. 切「人声场景」(纯净CD版 / 演唱会版)微调低音抑制策略。
3. 用麦克风音源单独唱这一段——你自己的声音必然是最强源,不受伴奏干扰。

若换成 RMVPE 后仍然检不到,说明那个瞬间人声在录音里确实被压住了(实测遇到过:该处连 RMVPE 的
人声频段显著度也只有 1.3%),这属于素材本身的问题。若是**持续的**低八度显示并伴随曲线直升直降,
请连同时间点提交 Issues——v1.1.2 已修复其中一类(次谐波幻音),v1.2.0 又解决了"被伴奏抢线"。

## 使用

1. 双击启动 → 首次启动有新手引导(真实界面演示);
2. 右键小球选择音源(麦克风 / 系统声音 / 正在播放的应用),开唱即显示音高;
3. 把音频文件拖到主界面或小球上,选择算法与场景后离线分析;
4. 设置面板:人声场景、检测算法、主题、背景图与虚化、强调色、小球颜色模式。

## 算法

基于 [pYIN](https://code.soundsoftware.ac.uk/projects/pyin)(YIN 概率阶段 + 隐马尔可夫平滑),C# 独立实现;针对真实使用场景做了以下增强(见 `PitchBall/Audio/` 源码注释):

- 假声(近似纯音)的次谐波消歧:次谐波求和(SHS)在候选谐波链内按谱能量选基频,并有连续帧迟滞防误触发;
- 高音"次谐波幻音"兜底:周期信号在 T、2T、3T 处的谷几乎等深,而 HMM 转移窗口只有 ±1 半音、无法跨八度,一旦锁在次谐波上整段高音都会被报成低 2~4 个八度(即便候选概率完全支持真基频)。现按"报告音高在谱上几乎不存在、而另有候选支撑充分"判定并改写,且真基频弱(假声基波弱、2 次谐波反超)的帧不受影响;
- 真声/混声/假声分类:H1–H2 谐波能量比 + 次谐波链结构判据;
- 伴奏贝斯抑制:分场景的频率先验(通用/纯净CD版/演唱会版);
- 和声与多声部鲁棒:观测概率 IIR 时间平滑 + 显示级锚点式防跳变/防触底;
- 检测算法可在设置中切换:**pYIN(默认)/ 原手写 YIN / RMVPE**。
- **RMVPE(神经人声模型)**:RVC 社区的人声基频模型,ONNX 推理、纯 CPU(20 倍实时以上),
  模型以 INT8 量化内嵌(约 94MB,精度与 fp32 一致:定标偏差 ≤3 音分、与 fp32 输出一致率 99.3~99.6%)。
  前端与上游一致:16kHz / 窗 1024 / 跳 160(10ms 一帧)/ 128 mel(HTK,fmin 30,fmax 8000)
  / 居中 reflect 补零 / 时间维补零到 32 的倍数;输出取显著度最大箱的 ±4 箱加权平均。
